# 百度网盘消息解析逻辑

## 核心规则
**目录名称**: 从消息中提取 (如 `260723`, `260724`) - 用于按日期分类管理
**提取码**: 从配置中读取 (默认 `0409`) - 用于统一访问权限

## 正确实现逻辑

### 消息解析行为
- **钉钉格式**: `260723：https://...` → 目录名: `260723`, 提取码: `0409`
- **飞书格式**: `提取码 260723\n链接：https://...` → 目录名: `260723`, 提取码: `0409`  
- **纯链接格式**: `https://...` → 目录名: `0409`, 提取码: `0409`

### 技术实现
在 `src/feishu/message_parser.py` 中：
```python
# 目录名称从消息中提取
folder_name = match.group(1)  # 如260723

# 提取码从配置中取
extraction_code = self.settings.message_default_extraction_code  # 默认0409
```

## 常见错误和纠正

### 错误理解: 目录名称总是0409
❌ **错误**: 无论消息内容如何，目录名称总是使用默认提取码
✅ **正确**: 目录名称应该从消息中提取，便于按日期分类

### 错误理解: 提取码从消息中取
❌ **错误**: 从消息中解析提取码用于访问
✅ **正确**: 提取码从配置中统一读取，实现统一访问权限

## 配置管理

### 关键配置项
```env
MESSAGE_DEFAULT_EXTRACTION_CODE=0409
```

### 配置说明
- 这个提取码用于访问所有接收到的百度网盘链接
- 企业可统一配置为企业的提取码
- 默认值 `0409` 是常用通用提取码

## 目录结构优势
按日期分类的目录结构：
```
百度网盘根目录/
├── 260723/    # 7月23日的报告
├── 260724/    # 7月24日的报告
├── 260725/    # 7月25日的报告
└── 0409/      # 无明确日期的文件
```

## 测试验证

**重要**: 这个逻辑是系统设计的核心，修改时必须完全理解业务需求。

## 为什么这样设计？

1. **按日期分类**: 每天有独立目录，便于查找特定日期的报告
2. **统一访问**: 所有链接使用同一提取码，简化权限管理
3. **灵活配置**: 支持企业统一提取码配置
