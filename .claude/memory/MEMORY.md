## 使用指南

### 修改代码前
1. 阅读 [代码修改检查清单](code-review-checklist.md)
2. 检查 [代码质量问题模式库](code-quality-patterns.md) 中的相关模式
3. 特别注意：重复代码、条件分支重复、遗留实现

### 添加新功能时
1. 优先考虑复用现有通用逻辑
2. 添加通用逻辑后，立即删除被替代的特定实现
3. 不要说"以后再重构"，现在就重构

### 代码审查时
1. 搜索相同的方法调用是否有多个位置
2. 检查if-else分支是否有重复逻辑
3. 确认没有遗留的调试代码或临时方案

## 重要提醒

**重构时机**：添加新功能是重构的最佳时机，不要错过！

**遗留问题**：代码演进过程中最容易产生遗留问题，扩展功能时必须审查现有代码。

**统一原则**：相同功能只在一个地方实现，通过参数或配置处理差异。
