# 百度网盘PDF文件自动传输系统 v1.4.2 最终发布 (目录名称修复版)

## 🎯 **重要修复：目录名称逻辑**

### **用户反馈的问题**
用户发现即使设置了默认提取码 `0409`，系统仍然从消息中解析不同的提取码作为目录名称。

### **修复前的问题**
- 消息 `260723：https://pan.baidu.com/s/...` → 目录名称: `260723` ❌
- 消息 `提取码 260723\n链接：https://...` → 目录名称: `260723` ❌
- 消息 `https://pan.baidu.com/s/...` → 目录名称: `0409` ✅

### **修复后的行为**
- 消息 `260723：https://pan.baidu.com/s/...` → 目录名称: `0409` ✅ 提取码: `260723` (用于访问)
- 消息 `提取码 260723\n链接：https://...` → 目录名称: `0409` ✅ 提取码: `260723` (用于访问)
- 消息 `https://pan.baidu.com/s/...` → 目录名称: `0409` ✅ 提取码: `0409` (默认)

### **核心改进**
现在目录名称**总是使用默认提取码 `0409`**，无论消息中包含什么提取码。

消息中的提取码（如果存在）仍然被保留用于实际访问百度网盘链接，但目录名称统一使用默认值。

## 🔧 **技术细节**

### **修改的文件**
- `src/feishu/message_parser.py` - 消息解析器逻辑

### **修改内容**
```python
# 修改前：使用消息中的提取码作为目录名称
folder_name = extraction_code  # ❌ 会产生不同的目录名

# 修改后：总是使用默认提取码作为目录名称
folder_name = self.settings.message_default_extraction_code  # ✅ 总是0409
# 但保留消息中的提取码用于访问百度网盘
extraction_code = message_extraction_code  # 用于实际访问
```

### **逻辑说明**
1. **目录名称**: 总是使用 `MESSAGE_DEFAULT_EXTRACTION_CODE` (默认 `0409`)
2. **访问提取码**: 
   - 如果消息包含提取码，使用消息中的提取码访问链接
   - 如果消息不包含提取码，使用默认提取码访问链接

## 💡 **使用优势**

### 统一目录管理
- 🎯 **一致的目录结构**: 所有文件都保存到 `/0409` 目录
- 🎯 **简化管理**: 不需要为每个不同提取码创建单独目录
- 🎯 **减少混乱**: 避免网盘中出现大量不同名称的目录

- 🎯 **提取码兼容**: 仍然使用消息中的正确提取码访问链接
- 🎯 **访问成功率**: 不会因为统一目录名称而影响文件访问
- 🎯 **向后兼容**: 支持所有现有消息格式
